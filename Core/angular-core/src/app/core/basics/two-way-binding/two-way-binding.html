Angular Two-Way Data Binding - Notes

Definition: Two-way data binding means data can flow in both directions: from component to HTML and from HTML back to the component.

Component → HTML: When the component value changes, the HTML is updated.

HTML → Component: When the user changes the input, the component value is updated.

In short: Component ↔ HTML

1. Old / Traditional Way - ngModel

Angular provides ngModel for two-way data binding.

Syntax: [(ngModel)]="username"

It combines property binding and event binding into one syntax.

[(ngModel)] is commonly called banana in a box syntax.

Example: input changes → username changes → HTML updates automatically.

Requirement: FormsModule must be imported to use ngModel.

2. New / Signal Way

With Signals, we can explicitly combine property binding and event binding.

Example: [value]="name()"

This sends the Signal value from the component to the HTML.

Example: (input)="name.set(...)"

This sends the changed input value from the HTML back to the Signal.

So: Signal → HTML and HTML → Signal

In short: [value] + (input) = two-way data flow.

3. Two-Way Binding with Signal Object

A Signal can also contain an object.

Example: user = signal({ name: 'Akshay', age: 25 })

To update only the name, we use update().

update(user => ({ ...user, name: newName }))

The spread operator (...user) keeps the existing properties and changes only the required property.

Similarly, age can be updated using: update(user => ({ ...user, age: user.age + 1 }))

Property Binding vs Event Binding

[value] → Component → HTML

(input) → HTML → Component

[(ngModel)] → Both directions together

Easy Flow

User types in input → input event → Signal updates → Angular updates HTML

In short: Two-way binding = Component ↔ HTML.
